# Content Room demo guide

## 90-second story

Start with the problem: "Publishing is usually a one-way bet. You only learn what
people ignored after the post is already live."

Paste a campaign URL, a direct image/video URL, or upload media. Name a target
audience and select the channel. Show the preview, then start the rehearsal.

As the room fills, say: "Content Room turns the creative into content DNA, grounds
a reusable synthetic audience, and simulates exposure, attention, interpretation,
decision, and action." Emphasise that this is a hypothesis engine, not a claim that
synthetic agents are real people.

Open the results in this order:

1. **What happened:** stop, trust, and action signals.
2. **Who reacted differently:** audience segments and individual reactions.
3. **Why:** the interpretation and reasoning behind the strongest split.
4. **What to change:** the concrete hook, proof, and CTA recommendation.
5. **Version B:** revise the content, keep the same audience, then compare runs.

Close with: "We do not replace validation. We help a team arrive at a better first
test before it spends creative budget or audience trust."

## Live-demo reliability

Use a pre-prepared direct media URL as a backup. For a live OASIS demonstration,
confirm `/health` before presenting. If the Python service is unavailable, the app
uses its deterministic local fallback and keeps the experience usable; disclose that
fallback rather than implying the remote simulation ran.
